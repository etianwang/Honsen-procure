After checking those conditions, an isolated operator released the retained lock and unmasked the service; no grant was issued by the driver. A second controller run on the same database restored USAGE through the production grant mechanism, published successfully and the API role inserted successfully.

[Initial run 39822815486](https://github.com/etianwang/Honsen-procure/actions/runs/39822815486) demonstrated the revoke/readiness behavior but recovery failed preflight because the fixture had left the service masked. The driver was amended to unmask during operator recovery; the complete rerun above passed. This was fixture recovery preparation, not a sequence permission defect.
