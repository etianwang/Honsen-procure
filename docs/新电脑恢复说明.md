# 新电脑恢复开发｜最简说明

唯一进度入口：[交接进度表](交接进度表.md)。源码和说明都在原GitHub仓库，无须从微信搬源码，也不依赖原电脑的盘符或聊天记录。

## 1. 准备工具

Windows：Git、Node.js **24.18.0**、Rust MSVC、Visual Studio C++ Build Tools/Windows SDK、WebView2、Codex。隔离PostgreSQL16使用WSL2 Ubuntu内Docker Engine/Compose/Buildx。

Mac：Git、Node.js **24.18.0**、Rust、Xcode Command Line Tools、Codex；隔离PostgreSQL16使用Colima及对应Docker context。Mac可继续前端/API/共享包/适配后的Rust；Windows安装器、Credential Manager、注册表、UAC和Toolbox验收仍须Windows。

## 2. 取回进度与源码

在自选空目录执行：

```sh
git clone --branch codex/handover-docs-20261025 https://github.com/etianwang/Honsen-procure.git Honsen-procure
cd Honsen-procure
```

先读docs/交接进度表.md。默认接手统一RC时：

```sh
git fetch origin
git switch --detach f4756afdb01ebac7b17ae9016d9ad56ab450fea5
node --version
npm ci
npm run typecheck
npm run test --workspace @honsen/shared
npm run test --workspace @honsen/desktop
```

若接手付款，选origin/codex/procurement-t09a；采购业务选origin/codex/v1-business-flow；需找未提交代码才看HONSEN-V1-HANDOVER/BRANCH-STATUS.md的wip分支。先核对GitHub最新SHA；WIP未经功能验收，冲突现场不能当RC。开始开发时新建自己的codex/分支，不在main开发。

不重复安装缓存，不重生成package-lock.json，不使用生产数据库跑测试。完整环境/构建命令仅在需要时读[详细说明](NEW-COMPUTER-SETUP.md)。大型安装/API包从GitHub交接Draft下载。

## 3. 需要敏感配置时

从自己保存的文件取回“弘盛采购系统-敏感资料加密备份-2026年10月25日.aesgcm”和“弘盛采购系统-恢复密钥-请单独保管.txt”。取得交接分支中的HONSEN-V1-HANDOVER/decrypt-private-backup.cjs，执行：

```sh
node decrypt-private-backup.cjs "弘盛采购系统-敏感资料加密备份-2026年10月25日.aesgcm" "弘盛采购系统-恢复密钥-请单独保管.txt" --verify
node decrypt-private-backup.cjs "弘盛采购系统-敏感资料加密备份-2026年10月25日.aesgcm" "弘盛采购系统-恢复密钥-请单独保管.txt" private-restored.zip
```

先认证再解密，解压到私人目录；按包内PRIVATE-INVENTORY.json找配置，不原样套用旧电脑绝对路径。不要把明文ZIP/.env上传GitHub。业务SQLite恢复前先隔离核对outbox、附件和安装编号身份，不直接覆盖新数据库。Windows凭据库不能靠复制数据库迁移，须重新在线登录。
