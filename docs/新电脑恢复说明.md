# 新电脑恢复说明

先读[V1交接进度表](V1交接进度表.md)，它是唯一状态入口。源码和文档都在现有GitHub仓库，不依赖原电脑盘符或聊天记录，不需要搬截图和日志。

## 1. 安装环境

- **Windows**：Git、Node.js **24.18.0**、Rust MSVC、Visual Studio C++ Build Tools／Windows SDK、WebView2、Codex；PostgreSQL16隔离测试用WSL2 Ubuntu内Docker Engine／Compose／Buildx。
- **Mac**：Git、Node.js **24.18.0**、Rust、Xcode Command Line Tools、Codex；PostgreSQL16隔离测试用Colima及对应Docker context。

Mac可以继续前端、API、共享包及适配后的Rust开发；Windows安装器、Credential Manager、注册表、UAC和Toolbox原生更新验收必须在Windows完成。

## 2. 从GitHub恢复

在空目录执行，保留文档目录，再建立应用开发目录：

```sh
git clone --branch codex/handover-docs-20261025 https://github.com/etianwang/Honsen-procure.git Honsen-procure
cd Honsen-procure
```

读docs/V1交接进度表.md，然后：

```sh
git fetch origin
git worktree add --detach ../Honsen-procure-dev f4756afdb01ebac7b17ae9016d9ad56ab450fea5
cd ../Honsen-procure-dev
node --version
npm ci
npm run typecheck
npm run test --workspace @honsen/shared
npm run test --workspace @honsen/desktop
```

文档仍在旁边Honsen-procure目录，不会随应用checkout消失。需要接付款或业务分支时，按进度表选择对应分支并核对最新SHA；WIP未经功能验收，不能直接当RC。用户解除冻结后再建自己的codex/任务分支，不在main开发。锁文件不重生成，测试不连接生产数据库。

## 3. 取回敏感配置

把自己保存的中文敏感加密包和恢复密钥放在私人目录。在保留的**文档目录Honsen-procure**执行（参数可填写文件绝对路径）：

```sh
node HONSEN-V1-HANDOVER/decrypt-private-backup.cjs "弘盛采购系统-敏感资料加密备份-2026年10月25日.aesgcm" "弘盛采购系统-恢复密钥-请单独保管.txt" --verify
node HONSEN-V1-HANDOVER/decrypt-private-backup.cjs "弘盛采购系统-敏感资料加密备份-2026年10月25日.aesgcm" "弘盛采购系统-恢复密钥-请单独保管.txt" private-restored.zip
```

先认证再解密；解压到私人目录，按包内PRIVATE-INVENTORY.json找配置。不要把明文ZIP、.env、COS／SSH／数据库秘密或恢复密钥上传GitHub。SQLite先隔离核对outbox、附件和安装编号身份，不直接覆盖新数据库；Windows凭据库必须重新在线登录。
