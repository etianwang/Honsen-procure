# Build Tasks: Zero to Production

## Global completion gate

Every task is a separately reviewable vertical slice: **IMPLEMENT → TARGETED TEST → INDEPENDENT RECHECK → CLOSE**. The original dependency table below is retained. Missing implementation/security prerequisites or external authority block the affected slice; open final-acceptance prerequisites block parent closure, not every safe independent implementation. Disputed boundaries require approval. Historical partial work is not acceptance.

For **every task that changes code**, completion requires all of the following:

1. Run formatting, lint, strict typecheck, unit tests and production build for every affected package.
2. Add or update at least one focused test for new behavior, validation, authorization rule, migration or failure path.
3. For a changed UI acceptance boundary, run a reproducible DOM interaction test against the running application using Playwright. It must load the relevant route, locate controls by accessible role/name or label, simulate the primary click/type/keyboard path, and assert the visible result. A screenshot and browser-console check are retained as task evidence. Unchanged DOM evidence may be reused only with its SHA/scope and a boundary comparison; it does not replace required native proof.
4. For Tauri/Rust or API boundaries, include the relevant command/API integration test. For migration/sync changes, include retry/failure/conflict coverage.
5. Record executed commands, result, skipped checks, migration effect, sync effect and any remaining risk in the task completion note.

Manual browser clicking is useful for design review but does **not** replace the committed DOM test. Task 00 establishes the Playwright harness; later tasks extend it instead of using one-off scripts.

Run directly relevant tests and mandatory affected-package gates, not unrelated full suites. Retain original final-acceptance gates. Documentation-only work checks formatting, references and status consistency. Reuse bounded valid evidence; do not create extra NATIVE tasks or require nonessential Harness refactoring.
