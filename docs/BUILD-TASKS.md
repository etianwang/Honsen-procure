# Build Tasks: Zero to Production

## Global completion gate

Every task is a separately reviewable vertical slice. Do not start a dependent task until the prior task has passed its own gate.

For **every task that changes code**, completion requires all of the following:

1. Run formatting, lint, strict typecheck, unit tests and production build for every affected package.
2. Add or update at least one focused test for new behavior, validation, authorization rule, migration or failure path.
3. Run a reproducible DOM interaction test against the running application using Playwright. It must load the relevant route, locate controls by accessible role/name or label, simulate the primary click/type/keyboard path, and assert the visible result. A screenshot and browser-console check are retained as task evidence.
4. For Tauri/Rust or API boundaries, include the relevant command/API integration test. For migration/sync changes, include retry/failure/conflict coverage.
5. Record executed commands, result, skipped checks, migration effect, sync effect and any remaining risk in the task completion note.

Manual browser clicking is useful for design review but does **not** replace the committed DOM test. Task 00 establishes the Playwright harness; later tasks extend it instead of using one-off scripts.

## Explicit boundaries

- T00–T14 must not invent `appId`, EXE name, install location, Runner arguments, registry entries or update URL.
- T15 remains blocked until the permanent Toolbox identity is approved, even though automatic update is required for internal distribution.
- COS/PostgreSQL secret values remain outside Git and are never copied into tests, screenshots or task notes.
- Each task may use fixtures only; no real supplier contacts, prices, account credentials or production attachments.

## Suggested immediate next task

Start **T00**. Its purpose is to make every later task verifiable: repository shape, CI gates and an automated DOM harness. It does not add production business behavior or package the application.
