# Canonical stable Release source: approved bounded repair

Only TOOLBOX-JOINT-SCOPE item 1 is authorized and implemented here. The canonical URL is `https://api.github.com/repos/etianwang/Honsen-procure/releases/latest`. Build input and manifest generation use the same constant; noncanonical environment overrides fail before building. The NSIS hook writes the same URL to both UpdateManifestUrl and compatibility UpdateUrl. Existing installed registry values are not read, migrated or rewritten by this change.

The Toolbox's existing GetLatestVersionAsync is the actual runtime consumer of this URL and tag_name response. `scripts/github-stable-release.mjs` additionally provides a separately executable read-only contract consumer through `node scripts/check-github-stable-release.mjs`: it validates stable tag, non-draft/non-prerelease, exactly one version-matched Setup.exe asset (auxiliary Runner/diagnostic EXEs do not count), the same approved repository download URL and GitHub `sha256:` digest. HTTP, network, JSON or schema failure never returns an accepted installer. It neither downloads nor installs the asset. Native launch behavior and public Runner parameters/result JSON are unchanged; this checker is not wired into native launch.

`scripts/generate-github-release-manifest.mjs` and its `manifest.json` remain unchanged as a local artifact summary with their original fields/name. That file is not the canonical update-source API response, and its existence/digest is not evidence that GitHub has published a qualified stable asset. No release or catalog entry is created.

Focused regression covers canonical manifest values, hook's two registry URL fields, old/foreign override rejection, valid API response, malformed/draft/prerelease/missing digest/foreign URL/ambiguous installers, network/HTTP/JSON failures. Full tests/release execution results are reported to the orchestrator. No Cargo/build/install or P1 rerun is part of this slice. Live availability and Toolbox joint UI/apply acceptance remain separate gates; no new stable release is manufactured to satisfy a check.

Actual verification: `node --test tests/release/*.test.mjs` passed 14/14 with no skips. The live read-only `node scripts/check-github-stable-release.mjs` returned HTTP 404 and exit 1, correctly refusing to claim an available qualified stable release. Formatting and diff checks passed. This is a live-availability BLOCKER for joint update acceptance, not a reason to create a release or bypass the digest requirement.
