## Integration and release gates

- The existing `main` tip `5139cc8` is an ancestor of the integration candidate. Draft #13 is an ancestor as well. PRs #15–#18 have integration commits in the candidate. PR #19 payment-conflict implementation is represented by successor `0d0c80d`. The quote selection work from #20 is represented by successor `8bfa3d3`, and the current tree already has the authorized home queue and HPA issue flow. Do not replay old PRs. Open drafts #3 and #14 are not selected for this Alpha integration. #3 targets workflow deduplication, and #14 requires its own attachment-scope review.
- The initial hosted run `42536776329` stopped on formatting. `6f36a3a` fixed formatting and hosted run `42600666920` passed that step, then exposed a PostgreSQL fixture isolation error. A previous test on the same project published two extra entries. The ledger regression now reads after its pre-test cursor and asserts the exact four accepted IDs, including only the winning concurrent reversal. Production financial code and Staging data were unchanged by the repair.
- The repaired ledger suite passed 5/5 against isolated PostgreSQL 16 in WSL2. The disposable container and network were removed. Workspace lint, typecheck and build passed. The affected desktop Chromium suites passed 43/43, including Excel file readback, finance controls, receipt guards, project scoping and sync lifecycle. These browser fixtures do not use Staging.
- The Toolbox identity and update contracts remain as documented in [Toolbox integration](../HONSEN_TOOLBOX_INTEGRATION.md). The upstream Toolbox contract still records the extra launch arguments and missing third-party `apply` caller. Keep stable publishing and Toolbox catalog enablement outside internal Alpha. The release repository is public, so a GitHub prerelease there would also be publicly downloadable.
- Require the hosted `quality` check, an exact final-merge source and package fingerprint, and Windows installed smoke on the existing Staging environment before release. The smallest smoke covers launch, normal login, main navigation, existing records, critical readbacks and safe actions, sync acknowledgement and restart retention. Do not recreate accounts, orders, suppliers, payments or reversals for this smoke.

## Known issues

- The verified PDF is limited to the valid French-primary HPA scenario on 0.1.23. Historical orders with missing frozen translations remain blocked. SPO, OPA, other native PDF scenarios and physical printing remain open.
- Mobile payments and wallet configuration remain outside the accepted functionality. The tested financial operation is ledger registration and reversal.
- Complete Windows UX, accessibility and DPI coverage remains open. Preserve the exact source and scope for screenshots and results already collected.
- Treat any verified loss, cross-scope access, amount discrepancy or silent sync failure as a release blocker.
