## HPA native in Windows Sandbox

Current HPA runner is not directly portable to the installation Sandbox. It starts Windows Node/Vite/CDP and a local TLS test server backed by PostgreSQL; an offline-network Sandbox cannot reach the host loopback PostgreSQL or HTTPS service, and the installation staging has neither Node dependencies nor a PostgreSQL test service. The driver additionally assumes repository-relative modules/source metadata and explicit profile seeding binaries. Merely copying the EXE or changing a path cannot provide HPA business acceptance.

A separately authorized self-contained test package could run in one guest if it bundles trusted Node/runtime dependencies, the candidate EXE and profile seeder, frontend assets, server/migrations and an entirely guest-local disposable PostgreSQL service, plus a guest entry script that establishes fixture scope and TLS. It needs no COS credential or business snapshot. Only generated synthetic account/DB passwords and temporary test certificates would be used. Two independent guest-local profiles prove two installations on one guest, not two physical Windows machines. Do not map the source root or COS environment into the installation guest. Keep existing install/Runner/uninstall Sandbox evidence separate from this future business package.
